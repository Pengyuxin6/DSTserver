# 一脸懵逼也能看懂：饥荒服务器面板的图片系统完全指南

> 这份文档回答一个问题：**网页上那成千上万张小图标，到底是从哪来、怎么算出来、又怎么显示出来的？**
> 覆盖面：原版、猪镇（哈姆雷特）、海难、熔炉、三合一，五类世界的**全部图片算法**和**取图位置**。
> 看不懂代码也没关系，每一节都先讲人话，再给算法。

---

## 0. 三十秒总览

网页上每一张小图（物品、生物、世界设置、世界预设、模组图标），都按这条**优先级链**取图，一级找不到才往下一级走：

```
① 游戏图集切片（本地 PNG，秒开）
   ↓ 没有
② 模组自带图集切片（本地 PNG，秒开）
   ↓ 没有
③ 小地图图集切片（本地 PNG，生物/实体兜底）
   ↓ 没有
④ 社区图床补全（服务器后台取一次，落盘缓存）
   ↓ 没有
⑤ 首字符占位块（一个带颜色的圆角块，显示名字第一个字）
```

**关键认知：游戏里几乎没有"一张图一个文件"的小图标。** Klei（游戏开发商）把几百张小图拼进一张大贴图（叫**图集 / Atlas**，就是文档里说的"压缩图"），再配一个同名 `.xml` 文件记录"每张小图在大图的哪个位置"。面板的全部图片工作，本质就是三件事：

1. **解码**大贴图（KTEX 格式 → PNG）
2. **按 XML 坐标裁剪**出每张小图（切片）
3. **记住谁该用哪张小图**（映射）

## 2. 压缩图（图集）是什么：KTEX + XML + 切片算法

### 2.1 一分钟原理

- `.tex` 文件不是普通图片，是 Klei 私有的 **KTEX** 格式：一个文件头 + 压缩像素数据（DXT1 / DXT5 压缩，或未压缩 RGBA）。
- `.xml` 文件是"地图册目录"，每个元素记录小图在大图里的**相对坐标**（UV，0~1 的小数）：

```xml
<Atlas>
  <Texture filename="minimap_atlas.tex" />
  <Elements>
    <Element name="evergreen_lumpy.png" u1="0.2189" u2="0.2497" v1="0.3127" v2="0.3435" />
    ...
  </Elements>
</Atlas>
```

`u1/u2` 是左右边界（横向比例），`v1/v2` 是上下边界（纵向比例）。

### 2.2 切片算法（面板内置，零依赖）

```
1. 读 .tex 文件头：魔数 "KTEX" + 格式标记（0=DXT1, 2=DXT5, 4=RGBA）+ 宽/高
2. 按格式解码成大图 RGBA 像素数组：
   - DXT1/DXT5：按 4×4 像素块解码（每块 8/16 字节，含 2 个基准色 + 16 个 2-bit 索引）
   - RGBA：直接拷贝
3. 对每个 XML 元素：
   裁剪框 x = u1 × 图宽, 宽 = (u2-u1) × 图宽
          y = v1 × 图高, 高 = (v2-v1) × 图高
   （注意：KTEX 像素自上而下，v 原点在上方，不用翻转）
4. 把裁出来的小 RGBA 编码成 PNG（内置 zlib deflate 实现），
   存到 public/icons/<图集名>/<元素名>.png
```

**实现位置**：线上运行时用 `panel/src/server.ts` 的 `decodeKTEX()` / `cropPNG()`（边用边切边缓存）；批量预切用工具 `panel/tools/extract_icons.ts`：

```bash
# 切某个模组的全部图集（例：猪镇模组）
bun run tools/extract_icons.ts --mod 3322803908 --mods-dir /home/steam/dst_mods

# 切游戏小地图图集（本地有客户端时）
bun run tools/extract_icons.ts --minimap --server-dir "D:\steam\steamapps\common\Don't Starve Together"
```

### 2.3 科雷四类图集的差异对照（解析时最容易踩的坑）

科雷不同时期、不同用途的图集**命名规则并不统一**，用一套正则硬套会整组漏掉。面板解析索引时统一用 `<Element name="xxx.(tex|png)"` 兼容两种后缀（`server.ts` 的 `itemIconAtlas()`）：

| 图集类型 | 文件（客户端 data/ 下） | 元素名后缀 | 内容 | 数量级 |
|---|---|---|---|---|
| 物品栏图集 | `images/inventoryimages1~4.xml + .tex` | `.tex` | 物品/建筑/配方图标 | 1024×3 + 223 |
| 小地图图集 | `minimap/minimap_data*.xml + minimap_atlas*.tex`（**3 组**，data.xml↔atlas.tex、data1↔atlas1、data2↔atlas2） | `.png`（科雷原始命名就是 png！） | 世界实体的小地图标记（树、矿石、触手、箱子、蘑菇等） | 547（3 组合并去重） |
| 世界设置图集 | `images/worldsettings_customization.xml + .tex`、`worldgen_customization.xml + .tex` | `.tex` | 编辑世界界面的设置项图标 | 158 + 83 |
| 模组封面 | 模组目录里的 `modicon.tex` | 单文件，无 XML | 模组头像 | 每模组 1 张 |

要点：
- **小地图 XML 的元素名以 `.png` 结尾**（如 `glommer.png`），物品栏的以 `.tex` 结尾（如 `log.tex`）——不是 bug，是科雷原本就这么写的；解析少兼容一种后缀，547 个小地图图标会**全部静默失踪**（大触手、大号华丽箱子、格罗姆这类"只有小地图图标"的实体就全没图了）。
- 小地图 3 组文件的 data 与 atlas 是**按编号配对**的，切错组合会导致 UV 落到错误区域（切出来的图是别的实体）。
- 物品栏图集按 1024 个元素一张塞满再开下一张（1~3 各 1024、4 号 223），**游戏版本更新后元素会重新排列**——索引 XML 与 TEX 必须来自同一版本，否则全员错位。
- 模组里的物品图集与原版同格式，用同一套切片算法。

## 3. 原版世界的图片算法

### 3.1 物品图标（3944 个 prefab）

```
物品 prefab（如 "berries"）
  → 查索引 data/invicons/*.xml（元素名 → 图集名）
    · inventoryimages1~4.xml：3295 个物品栏图标
    · minimap.xml：547 个小地图图标（3 组游戏图集合并，工具自动生成）
  → 命中 → icons/<图集名>/<prefab>.png
  → 未命中（多为特效/无图实体）→ 走 §5 社区图床补全
```

**覆盖率全量扫描结论**（3944 个原版 prefab，逐一核对索引与磁盘 PNG）：

| 分类 | 数量 | 说明 |
|---|---|---|
| 图集直接覆盖 | 1662 | 科雷官方图（物品栏或小地图），本地秒开 |
| 仅社区图床兜底 | 715 | 有正式英文名但科雷没给图标（Boss、随从、洞穴装置等，如悲惨的毒菌蟾蜍 toadstool_dark） |
| 内部实体 | 1567 | 无英文名（`_fx` 特效、投射物、逻辑节点），本来就没图，显示占位块是**正常行为** |

物品列表实际展示 2370 个有名字的条目，其中 1633 个带图集图标。

### 3.2 世界设置/世界生成图标（236 个设置项）——**权威映射算法**

这是踩过坑的地方：设置项的**键名**和图集里的**元素名经常不一样**（`crow_carnival` 的图标文件叫 `crowcarnival`、`antliontribute` 叫 `antlion_tribute`）。按名字猜会漏 90 个。

正确做法是读游戏自带的权威对照表 `scripts/map/customize.lua`：

```lua
["antliontribute"] = {value = "default", image = "antlion_tribute.tex", world={"forest"}},
```

**映射生成算法**（一次性离线生成，结果存 `panel/data/worldoption_icons.json`）：

```
1. 从 scripts.zip 抽出 scripts/map/customize.lua
2. 逐个匹配 ["key"] = { ... } 条目：
   用"花括号配对"找条目体（不能用 [^}] 简单正则——
   条目里有 options_remap={...} 嵌套表，会把相邻条目吞掉，曾因此漏 15 条）
3. 条目体内取 image = "xxx.tex" → 元素名
4. 在客户端全部 345 个图集 XML 里找该元素 → 图集名
   （同一元素出现在多个图集时，优先 worldsettings_customization > worldgen_customization > 其他；
    例如 winter 同时出现在 thankyou_winter 和 worldsettings，必须选后者）
5. 游戏表里没有的 3 个特殊项手工补充：
   crow_carnival → crowcarnival ｜ portal_spawnrate → monkeyportal ｜ specialevent → events
6. 输出 { "antliontribute": {"atlas":"worldsettings_customization","img":"antlion_tribute"}, ... }
```

运行流程：后端 `worldOptionTable()` 给每个设置项附上 `icon`，前端按 `icons/<atlas>/<img>.png` 精确取图（旧的名字猜测作兜底）。**236 个设置项全部有图**。

### 3.3 世界预设图标

原版预设（生存/无尽/轻松等）走 cluster.ini 的 game_mode，不涉及图集；世界分类图（地上/地下）用 `worldgen_customization` 里的对应元素。

## 4. 模组世界的图片算法（猪镇 / 海难 / 熔炉 / 三合一）

先分清两种模组世界（面板"类型"列的徽章就是这么判断的）：

| 类型 | 判断标准（modworldgenmain.lua 代码特征） | 效果 |
|---|---|---|
| **地图·覆盖世界**（replace） | 出现 `AddLevel(LEVELTYPE.…`、`AddWorldGenLevel(LEVELTYPE.…` 或 `AddPreset(`，或有非原版预设 | 完全替换世界生成，原版设置不适用；只能同时开一个 |
| **生态·叠加设置**（extend） | 只有 `AddLevelPreInitAny` 之类 | 在原版世界基础上加内容，原版设置仍有效 |

### 4.1 通用解析算法

```
modworldgenmain.lua  → 判断 replace / extend（上表正则）
scripts/map/customize_patch.lua → 模组世界设置项（标准格式）：
   每个选项含 { key, label, 可选值, 图标图集 atlas, 图标文件 img }
modcustomizeitems.lua   → 猪镇系模组专用格式（pl_customize_table / customize_items）
scripts/map/levels/*.lua → 模组世界预设（含 location 字段区分地上/地下）
```

前端按 `icons/<atlas>/<img>.png` 取模组设置图标——这些图集已从模组 `images/` 目录预切到 `public/icons/`（用 §2.2 的工具 `--mod` 模式）。

### 4.2 猪镇（哈姆雷特 / Porkland）

- **典型模组**：Porkland（3322803908 等）。
- **世界设置图标**：模组自带图集 `customization_porkland.xml/.tex`（93 个元素，已切好）。设置项定义在 `modcustomizeitems.lua` 的 `pl_customize_table`（分组 → items，每项带 atlas/img）。
- **物品图标**：模组自带 `pl_inventoryimages`（703 个已切）、`pl_minimap`、`pl_hud` 等 pl_* 系列图集。
- **世界预设**：`SURVIVAL_PORKLAND` 类预设，location 不含 cave/under → **纯地上世界，不需要地下分片**；面板启用这类模组时会自动删除 Caves 分片（不然洞穴会崩）。
- **预设图**：取 `customization_porkland` 里与预设同名的元素。

### 4.3 海难（Shipwrecked）

- **世界设置图标**：`customization_shipwrecked`（60 个）+ `customization_shipwrecked2`（11 个），均已切好。
- 解析方式与猪镇相同（customize_patch / modcustomizeitems 两种格式都兼容）。
- 海难预设带火山（volcano）时 location 含 "volcano"，面板按 `/volcano|cave|under/i` 判定为"地下类预设"，主/副世界自动各选各的。

### 4.4 熔炉（The Forge / Lavaarena）与暴食（Quagmire）

- **这两个是 Klei 官方活动模式，内容就在原版游戏里**，不是模组：
  - 预设在原版 `LEVELTYPE.LAVAARENA` / `QUAGMIRE`（面板预设白名单 `VANILLA_PRESETS`）。
  - 图标走原版通道：物品在 inventoryimages1~4（搜 `lavaarena_`、`quagmire_` 前缀），实体在小地图图集。
- 面板把它们识别为"原版预设"，不会被误判成模组世界。

### 4.5 三合一（海难+猪镇+原版大融合）

- 代码特征：**只有 `AddLevelPreInitAny`**（在原版关卡初始化前注入内容），没有 AddLevel/AddPreset → 判定为 **extend（生态·叠加设置）**，不是 replace。
- 因此：原版 236 个设置项**仍然生效**，三合一自己的生态设置项**追加**显示；它和其他"覆盖型"地图模组**不冲突**（面板冲突检测只对 replace 型生效）。
- 图标：三合一模组自带 images/ 图集，按 §4.1 解析；世界预设是它的 levels/*.lua 注入到原版预设列表，预设图用模组图集。
- 性能提醒：三合一世界内容量大，单开世界吃内存（用户服务器 4G 内存门禁就是为这种情况准备的）。

## 5. 社区图床补全（最后的兜底，渠道对日志隐藏）

### 5.1 什么时候用到

实体**既没有物品栏图标、也没有小地图图标**（典型：阿比盖尔这种跟随生物）时，网页会请求后端 `/wiki-icon?prefab=<代码名>`，由服务器后台去社区图床取一张图，**取一次就落盘缓存**（`public/icons/wiki/<prefab>.png`），之后永久本地秒开。

### 5.2 取图算法（MediaWiki 存储规则）

MediaWiki（灰机 wiki 用的系统）存文件的路径是**可计算的**，不用调它的 API（API 有 Cloudflare 人机验证，服务器 IP 直接调会被拦；直取 CDN 没这个问题）：

```
1. 代码名 → 英文显示名：查 data/prefab_en_names.json
   （由游戏 strings.lua 的 STRINGS.NAMES 表离线生成，2802 条）
2. 文件名 = 英文名（首字母大写、空格→下划线）+ ".png"
   候选两个：原名 / 去撇号变体（如 Abigail's → Abigails）
3. 计算 md5(文件名)，取第 1 位和第 1~2 位十六进制当目录：
   https://<图床域名>/dontstarve/uploads/<md5第1位>/<md5前2位>/<文件名>
   例：Abigail.png → md5 以 88 开头 → .../8/88/Abigail.png
4. 下载 → 写磁盘缓存；全部候选失败 → 写 .404 负缓存（24 小时内不再重复请求）
5. 落盘前校验 PNG 魔数（89 50），防止把 CDN 的错误页当图片缓存下来
```

**取图必须走系统 curl，不能用语言自带 HTTP 客户端**（实战踩坑记录）：

- 图床有 Cloudflare 人机校验：**不带 UA** → 403 返回 "Just a moment..." 验证页；
- UA 版本号必须真实存在（随手编的 `Chrome/150` 会被识别为伪造 → 403；用真实发布过的 `Chrome/126` → 200）；
- 更隐蔽的一层：**Bun/Node 的 fetch 与浏览器的 TLS 指纹不同**（JA3 特征），从机房 IP 请求时即使 UA 正确也必被 403——实测 43 服务器上 Bun fetch 403、同参数 curl 200。因此后端改为 `Bun.spawn` 调**系统 curl**（Linux 与 Win10+ 均自带 `curl.exe`），借它的 TLS 栈过校验。
- 注意负缓存只代表"当时没取到"：取图链路修复后应清空 `public/icons/wiki/*.404` 重试，否则历史失败会继续挡 24 小时。

### 5.3 隐藏渠道（用户要求）

- 后端**不打印**任何含图床地址的日志；失败也静默换下一个候选。
- 前端只看到一个中性的 `/wiki-icon?prefab=xxx`，看不到来源。
- 磁盘缓存目录名 `public/icons/wiki/` 不含任何第三方域名。

## 6. 数据文件清单（都在 panel/data/，均由游戏文件离线生成）

| 文件 | 内容 | 生成来源 |
|---|---|---|

## 7. 常见问题（FAQ）

**Q：为什么有的物品显示一个色块加首字？**
它是特效/投射物（名字多带 `_fx`），游戏里本来就没有图标；或者社区图床也没有这张图（极少）。

**Q：服务器上没有客户端，能切物品图吗？**
不能，专用服务端不带物品栏图集。在本地面板切好后，`panel/public/icons/` 整个目录随部署/git 同步到服务器即可（这正是目前的做法）。

**Q：模组更新了图标会变吗？**
模组物品图标是运行时现切现缓存的（`/mod-icon`），模组文件一变缓存自动失效；模组封面图（`/local-icon`、`modicons/` 缓存）以文件内容为准，模组更新后删除对应 `public/modicons/<ID>/` 目录即可强制重建。

**Q：社区图床取图失败会怎样？**
写 `.404` 负缓存，24 小时内不再尝试；网页显示首字符占位块，不影响任何功能。

**Q：想手动刷新某张社区图？**
删掉 `public/icons/wiki/<prefab>.png`（和可能的 `.404` 文件）即可，下次访问自动重取。

**Q：毒菌蟾蜍/工具棚/大触手/华丽箱子/格罗姆/厨师袋/传送焦点这些图曾经"解压失败"？**
排查结论（可作为排障样板）：这些图的切片本身全部正常，逐张目检与游戏内一致。真正的故障链路是——① 它们多数**只有小地图图标**（格罗姆、大触手、大号华丽箱子）或**根本没有官方图标**（悲惨的毒菌蟾蜍 toadstool_dark、大触手的另一形态 tentacle_garden），后者走社区图床兜底；② 图床 CDN 升级人机校验后批量取图失败，留下的 `.404` 负缓存把修复后的重试也挡了；③ 浏览器还缓存着旧的失败状态。处理：清空 `public/icons/wiki/*.404` → 重启面板 → 浏览器 `Ctrl+Shift+R` 硬刷新。排查手法：先查索引有没有（`data/invicons/*.xml`），再查磁盘 PNG 在不在，再 `curl` 面板地址看 HTTP 状态码，最后才怀疑切片算法。
