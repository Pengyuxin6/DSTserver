# 饥荒联机版（DST）专用服务器模组迁移指南

> 本文档基于对本机 `D:\steam\steamapps\common\Don't Starve Together` 实际文件结构的分析，并结合网络上多方搭建教程整理而成。适用于将本地（客户端）已订阅/已启用的模组迁移到 **专用服务器（Dedicated Server）** 上运行。

---

## 一、关键概念：本地模组 vs 服务器模组

| 类型 | 说明 | 谁需要安装 |
|------|------|-----------|
| **服务器模组（Server Mod）** | `modinfo.lua` 中 `client_only_mod = false`，运行在服务端，影响世界规则、生物、物品等。若 `all_clients_require_mod = true`，则所有进入服务器的玩家都必须订阅该模组。 | 服务器**必须**安装 |
| **客户端模组（Client-only Mod）** | `modinfo.lua` 中 `client_only_mod = true`，只影响使用它的玩家本地（如 UI 美化、小地图标记等），不影响世界。 | 服务器**不需要**安装，玩家自行订阅即可 |

> 因此迁移时，**只需要迁移服务器模组**；纯客户端模组无需放到服务器。

---

## 二、本地模组的两个存放位置

饥荒联机版的 Steam App ID 为 **322330**。模组在本机有两个相关目录：

### 1. 游戏安装目录下的 mods 文件夹（服务器实际读取的位置）

```
D:\steam\steamapps\common\Don't Starve Together\mods\
```

该目录下的模组文件夹以 **`workshop-{模组ID}`** 命名，例如：

```
mods/
├── dedicated_server_mods_setup.lua   ← 服务器启动时自动下载模组的配置文件
├── modsettings.lua                   ← 客户端强制启用/调试用配置
├── INSTALLING_MODS.txt
├── workshop-362175979/               ← 例：Wormhole Marks（虫洞标记）
│   ├── modinfo.lua
│   ├── modmain.lua
│   ├── modicon.xml / modicon.tex
│   ├── scripts/
│   └── ...
├── workshop-1216718131/
└── ... (共约 48 个 workshop- 文件夹)
```

> **专用服务器和客户端共享同一个 `mods` 文件夹**。如果你在本机同时安装了客户端和 `Don't Starve Together Dedicated Server` 工具，它们读取的是同一个目录。

### 2. Steam 创意工坊缓存目录（Steam 自动下载的原始位置）

```
D:\steam\steamapps\workshop\content\322330\
```

Steam 订阅模组后，文件首先下载到这里，文件夹名**仅为纯数字 ID**（无 `workshop-` 前缀），例如：

```
322330/
├── 1289779251/        ← 模组 ID（对应 Cherry Forest）
│   ├── modinfo.lua
│   ├── modmain.lua
│   ├── mod.manifest
│   ├── scripts/
│   ├── anim/
│   └── ...
├── 1595631294/
└── ... (共约 159 个文件夹)
```

> Steam 客户端在启动饥荒时会自动把这里的模组同步/解包到上面的 `mods\workshop-{ID}` 目录中。**专用服务器不会自动做这个同步**，所以服务器迁移时需要手动处理。

### 模组 ID 从哪里获取？

- 创意工坊页面 URL 末尾的数字即为模组 ID，例如：
  `https://steamcommunity.com/sharedfiles/filedetails/?id=362175979` → ID 为 `362175979`
- 在游戏内模组列表中右键 → 复制网页链接，同样取末尾数字。

## 三、模组文件结构分析

每个模组文件夹的核心文件是 **`modinfo.lua`**，它决定了模组的元数据和加载行为。关键字段：

```lua
name = "Wormhole Marks"              -- 模组名称
version = "1.4.5"                    -- 版本号
api_version = 10                     -- API 版本（10 = DST）

-- ★ 以下三个字段决定了模组在服务器上的行为，迁移时务必留意
all_clients_require_mod = true       -- true: 所有进服玩家都必须安装此模组
client_only_mod = false              -- true: 纯客户端模组，服务器无需安装
dst_compatible = true                -- 是否兼容联机版

configuration_options = { ... }      -- 模组的可配置选项（对应 modoverrides.lua 里的配置）
```

| 字段 | 值 | 含义 |
|------|-----|------|
| `all_clients_require_mod` | `true` | 进服玩家必须订阅，否则无法加入 |
| `all_clients_require_mod` | `false` | 仅服务器需要，玩家可选 |
| `client_only_mod` | `true` | 纯客户端，**服务器不需要装** |
| `client_only_mod` | `false` | 服务器模组，服务器必须装 |

## 四、服务器加载模组的三种方式（核心）

专用服务器加载模组涉及 **两个层面**，缺一不可：

```
┌─────────────────────────────────────────────────────────┐
│  第一层：模组文件存在于服务器 mods 目录（下载/复制）       │
│         → 通过 dedicated_server_mods_setup.lua 或手动复制 │
├─────────────────────────────────────────────────────────┤
│  第二层：在存档中启用并配置模组                          │
│         → 通过 modoverrides.lua                          │
└─────────────────────────────────────────────────────────┘
```

只有文件没有启用，模组不会生效；只有启用配置没有文件，服务器会报错。**两者必须同时满足。**

---

### 方式一：自动下载（推荐，需服务器能联网 Steam）

编辑服务器 `mods` 目录下的 **`dedicated_server_mods_setup.lua`**：

```lua
-- 文件路径：服务器安装目录\mods\dedicated_server_mods_setup.lua

-- 每行一个模组 ID，服务器启动时会自动从创意工坊下载
ServerModSetup("362175979")    -- Wormhole Marks
ServerModSetup("378160979")    -- Global Player Positions
ServerModSetup("1216718131")   -- 中文翻译

-- 也可以下载整个创意工坊合集
-- ServerModCollectionSetup("合集ID")
```

> 此文件原始内容只有注释模板，需手动添加 `ServerModSetup("ID")` 行。服务器每次启动都会检查并更新这些模组。

---

### 方式二：手动复制模组文件夹（服务器无法联网时使用）

适用于服务器无法访问 Steam 创意工坊（如纯内网/Linux 离线环境）的情况。

**步骤：**

1. 在本机找到模组文件夹（两个位置任选其一）：
   ```
   来源 A：D:\steam\steamapps\common\Don't Starve Together\mods\workshop-{ID}\
   来源 B：D:\steam\steamapps\workshop\content\322330\{ID}\
   ```
2. 将该文件夹整体复制到服务器的 mods 目录：
   ```
   目标：服务器安装目录\mods\workshop-{ID}\
   ```
   > ⚠️ **注意**：放到服务器 `mods` 目录时，文件夹名必须是 **`workshop-{ID}`** 格式（带 `workshop-` 前缀）。如果来源是创意工坊缓存目录（纯数字 ID），复制后需重命名加上 `workshop-` 前缀。
3. 复制完不需要修改 `dedicated_server_mods_setup.lua`（因为文件已存在，无需下载）。

---

### 方式三：在存档中启用并配置模组（必须）

无论用方式一还是方式二把模组文件放好，都还必须通过 **`modoverrides.lua`** 告诉服务器"启用哪些模组、用什么配置"。

**`modoverrides.lua` 的位置（每个世界分片各一份）：**

```
存档根目录\Cluster_1\
├── cluster.ini              ← 集群配置（服务器名、密码、人数等）
├── Master\                  ← 地表世界分片
│   ├── server.ini
│   ├── worldgenoverride.lua
│   ├── modoverrides.lua     ← ★ 地表模组启用配置
│   └── save\
└── Caves\                   ← 洞穴世界分片
    ├── server.ini
    ├── worldgenoverride.lua
    ├── modoverrides.lua     ← ★ 洞穴模组启用配置
    └── save\
```

存档根目录通常位于：

```
Windows:  %USERPROFILE%\Documents\Klei\DoNotStarveTogether\Cluster_1\
Linux:    ~/.klei/DoNotStarveTogether/Cluster_1/
```

**`modoverrides.lua` 格式：**

```lua
return {
  ["workshop-362175979"] = {
    configuration_options = {
      ["Draw over FoW"] = "disabled"     -- 对应 modinfo.lua 中的配置项
    },
    enabled = true                        -- ★ true 表示启用
  },

  ["workshop-378160979"] = {
    configuration_options = {
      ENABLEPINGS = true,
      FIREOPTIONS = 2,
      SHOWPLAYERICONS = true
    },
    enabled = true
  },

  -- 最简写法（不配置选项，仅启用）：
  ["workshop-1216718131"] = { enabled = true },
}
```

> **Master 和 Caves 两个 `modoverrides.lua` 的内容通常保持一致**。如果模组只在某个分片生效，也可只写在对应分片里。

## 五、完整迁移流程（从本机到远程服务器）

以下以"本机已配好模组，要迁移到远程专用服务器"为例：

### 第一步：在本机确认模组列表和配置

最简单的方法是**本机新建一个世界 → 在游戏内勾选并配置好所有模组 → 生成世界进入选人界面后退出**。这样游戏会自动生成一份完整的 `modoverrides.lua`。

本机存档位置：

```
%USERPROFILE%\Documents\Klei\DoNotStarveTogether\Cluster_1\Master\modoverrides.lua
```

（本机已存在的实际路径示例：`D:\pyx\Documents\Klei\DoNotStarveTogether\1169490681\Cluster_1\Master\modoverrides.lua`）

### 第二步：把模组文件放到服务器

**如果服务器能联网（推荐方式一）：**

编辑服务器的 `mods\dedicated_server_mods_setup.lua`，根据 `modoverrides.lua` 中所有 `workshop-{ID}` 的 ID 列表，逐个添加：

```lua
ServerModSetup("362175979")
ServerModSetup("378160979")
ServerModSetup("1216718131")
-- ... 对应 modoverrides.lua 中的每个模组
```

**如果服务器不能联网（方式二）：**

把本机 `mods\workshop-{ID}\` 文件夹逐个打包上传到服务器 `mods\` 目录下。

### 第三步：把 modoverrides.lua 放到服务器存档

将第一步得到的 `modoverrides.lua` 复制到服务器存档的 **Master** 和 **Caves** 文件夹中：

```
服务器存档根目录\Cluster_1\Master\modoverrides.lua
服务器存档根目录\Cluster_1\Caves\modoverrides.lua
```

### 第四步：启动服务器验证

启动专用服务器，观察日志（`master_server_log.txt` / `server_log.txt`）：

- 出现 `Sim paused` 表示启动成功。
- 如果模组加载失败，日志会显示缺失的模组 ID 或配置错误。

## 六、本机实际文件对照表

以下为本机实际存在的文件，便于理解：

| 文件 | 路径 | 作用 |
|------|------|------|
| 服务器模组下载配置 | `mods\dedicated_server_mods_setup.lua` | 启动时自动从创意工坊下载模组 |
| 客户端模组调试配置 | `mods\modsettings.lua` | 开发调试用（ForceEnableMod 等） |
| 模组文件夹 | `mods\workshop-{ID}\` | 服务器实际加载的模组（共约 48 个） |
| 创意工坊缓存 | `steamapps\workshop\content\322330\{ID}\` | Steam 自动下载的原始文件（共约 159 个） |
| 模组缓存 | `cached_mods\{ID}_0\` | 游戏加载后的缓存 |
| 存档模组启用配置 | `Documents\Klei\DoNotStarveTogether\Cluster_1\Master\modoverrides.lua` | 启用哪些模组及其配置 |

## 七、常见问题

### Q1：服务器提示"正在运行旧版本模组"

原因：服务器上的模组版本与本机/创意工坊不一致。

解决：
1. 停止服务器；
2. 删除服务器 `mods\` 目录下所有 `workshop-` 文件夹；
3. 删除 `mods\dedicated_server_mods_setup.lua`（或重新编辑）；
4. 重新配置 `dedicated_server_mods_setup.lua` 并启动服务器重新下载。

### Q2：玩家进服提示缺少模组

原因：模组的 `modinfo.lua` 中 `all_clients_require_mod = true`，但玩家未订阅。

解决：玩家需在创意工坊订阅对应模组；或在服务器端使用 `modoverrides.lua` 配置仅为服务端的模组。

### Q3：模组文件已在 mods 目录但没生效

原因：忘记写 `modoverrides.lua`，或对应模组的 `enabled` 没有设为 `true`。

解决：检查 Master 和 Caves 两个分片的 `modoverrides.lua`，确保目标模组 `enabled = true`。

### Q4：文件夹名前缀问题

- `mods\workshop-{ID}\` —— 必须带 `workshop-` 前缀。
- `steamapps\workshop\content\322330\{ID}\` —— 纯数字，无前缀。

手动复制时注意转换命名格式。

### Q5：本地客户端模组是否需要迁移？

不需要。`client_only_mod = true` 的模组（如纯 UI 美化）只影响玩家自己，服务器不加载也不会报错。迁移时通过 `modinfo.lua` 判断即可。
